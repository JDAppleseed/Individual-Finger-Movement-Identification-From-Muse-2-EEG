## What changed

The active live inference path uses CNN-LSTM again. The original March 19 2-M16 weights, scaler, temperatures, and deployment policy remain the historical reference. Feature ensembles are retained as offline research, with no live promotion.

The repository now documents the recording-to-report workflow, pins reference artifacts, separates baseline presets from research evidence, and lists removal candidates for owner review. Nothing on that removal list has been deleted. A later rewrite will start in a separate folder.

## Latest combined datasets

The comparison uses 14,672 windows from three recordings for 1-M16, 14,673 from four recordings for 2-M16, and 7,998 from two recordings for 3-M16. The 2-M16 corpus includes the corrected April sitting and retains its previously documented 522-window REST exclusion. Source signal and labels match the selected combined windows.

Models are trained separately with the same 60-epoch CNN-LSTM recipe and seed 43. Fitting, calibration, and test event groups are separated and checked for overlapping source signal. The calibration code no longer moves individual windows across event groups or falls back to a random-window split.

## Current offline comparison

| Subject | Action | Active finger | Joint | REST recall |
| --- | ---: | ---: | ---: | ---: |
| 1-M16 | 79.36% | 82.61% | 69.59% | 68.20% |
| 2-M16 | 79.20% | 79.16% | 76.07% | 76.35% |
| 3-M16 | 69.08% | 57.13% | 55.12% | 73.80% |

These are unsmoothed classification results with temperature scaling only where calibration class coverage permits on retrospective within-subject event holdouts. Finger accuracy conditions on true movement, counting predicted REST as an error. They are not hardware-command metrics or unseen-session results.

The initial 1-M16 split incorrectly withheld its only remaining movement-session REST event for calibration. Correcting fitting coverage restored REST recall from 0% to 68.20%; doubling the REST weight raised it modestly to 71.13% in a diagnostic run. The weight-1 run remains the common-recipe comparison. Its calibration has no REST, so action/applicability temperatures use identity scaling. No new model is promoted. 3-M16 retains weak finger separation and session-confounded class coverage. The expanded 2-M16 dataset uses a different holdout from the March reference. No new run replaces the historical deployment checkpoint.

## Full-subject corpus evaluation

Full-corpus evaluation is available again as a separate diagnostic. It evaluates
all finite windows for one subject, including fitting and calibration data, using
the saved model, preprocessing, and temperatures. It performs no retraining,
random re-splitting, smoothing, or command gating.

| 1-M16 november | 14,672 | 85.35% | 86.06% | 77.19% | 95.86% |

These full-corpus results measure fit across the available recording corpus. They
are separate from held-out evaluation and gated command replay. Historical models
use their original corpora; November models use the expanded vetted corpora.
Their denominators and preprocessing differ, so these are not controlled model
comparisons. Missing original replay artifacts mean the May command-policy
headline is preserved as historical evidence, not claimed as reproduced by this
new classifier-only evaluation.

## Preserved published headlines

The published March 2-M16 saved-test figures remain **89.79% action**, **85.96%
finger on non-rest windows**, and **84.66% joint**. The March 1-M16 report remains
**83.94% action**, **80.61% finger**, and **92.11% REST recall** on its original
saved test split. The May full-corpus command summary remains **95.37% would-send
precision**, **91.11% event hit rate**, **86.42% committed joint accuracy**, and
**0.25% false REST actuation**. These historical values and their metric meanings
are preserved; the new evaluation does not overwrite them.

## Historical evidence and next steps

The May command-policy summary used the full March development corpus, including fitting/calibration data. Its original replay outputs were not recovered, so those numbers remain historical summaries rather than newly reproduced held-out performance.

The next phase must preserve raw recording/timebase integrity, event-aware splits, saved preprocessing, offline/live parity, command suppression, and immutable provenance. Prospective new-session recording and physical command validation remain necessary before claiming improved live utility.
