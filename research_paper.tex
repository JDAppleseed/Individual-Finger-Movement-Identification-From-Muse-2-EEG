\begin{abstract}
Real-time finger-level intention decoding from electroencephalography (EEG) is challenging due to low signal-to-noise ratio, temporal overlap of motor signals, and limited spatial resolution---limitations that are amplified by consumer-grade hardware. We present an end-to-end inference pipeline for finger movement decoding using a 4-channel Muse 2 EEG stream sampled at \TargetFsHz~Hz and labeled via time-aligned event markers. The system integrates sliding-window preprocessing (window \WindowSec~s, hop \HopSec~s), a multi-head CNN+LSTM classifier, and uncertainty-aware offline evaluation via Monte Carlo (MC) dropout. Across \NumSubjects subjects in the current repository run artifacts, mean test action accuracy is \ActionAccMean\% $\pm$ \ActionAccSD (range \ActionAccMin--\ActionAccMax) and mean finger accuracy on non-REST windows is \FingerAccMean\% $\pm$ \FingerAccSD (range \FingerAccMin--\FingerAccMax). Calibration is quantified using expected calibration error (ECE): \ActionECEMean (action) and \FingerECEMean (finger non-REST), computed from saved prediction bundles. These artifacts demonstrate the feasibility of subject-specific finger decoding with explicit calibration analysis and a deployment-oriented software stack.
\end{abstract}

\section{Introduction}

Finger-level motor intention decoding enables assistive robotics, prosthetic control, and adaptive human–machine interfaces. While clinical EEG systems with 32–128 channels have demonstrated robust motor decoding, such systems are expensive and rarely operate in fully real-time pipelines. Consumer-grade EEG devices offer accessibility but suffer from limited spatial resolution, dry electrodes, packet instability, and lower signal-to-noise ratio.

This work demonstrates a real-time, deployment-oriented finger-level decoding system built on the Muse 2 headset (4 channels, \TargetFsHz~Hz). Beyond top-line accuracy, we emphasize \emph{calibration and reliability} because downstream actuation (e.g., a robotic hand) is a safety-critical decision layer: an overconfident misclassification can be more harmful than a low-confidence abstention. We therefore treat uncertainty estimation (MC dropout) and reliability visualization as first-class evaluation outputs.

In the current run artifacts (two subjects), action decoding is more variable across subjects (SD \ActionAccSD~pp) than finger decoding on non-REST windows (SD \FingerAccSD~pp), consistent with the intuition that finger identity is more separable once non-REST movement is present.

We additionally report train--test generalization gaps from the saved training artifacts to contextualize potential overfitting under window correlation.

The pipeline provides:

\begin{itemize}
\item Continuous LSL-based EEG acquisition
\item Timestamp-domain aligned event labeling
\item Sliding-window preprocessing with NaN rejection
\item Multi-head CNN+LSTM classification
\item REST-aware class weighting
\item Deterministic evaluation (ECE) and MC-dropout uncertainty visualization
\item Artifact-driven reproducibility
\end{itemize}

\section{Related Work}
EEG motor decoding has a long history in motor imagery (MI) and event-related paradigms, with modern deep learning approaches often outperforming hand-crafted feature pipelines on within-subject decoding tasks. Compact convolutional models (e.g., EEGNet) and deeper CNN stacks have become common baselines for EEG classification and visualization. \cite{Lawhern2018EEGNet,Schirrmeister2017Deep}

Finger-level decoding is more challenging than binary MI due to weaker separability and the limited spatial resolution of scalp EEG; consumer devices further restrict spatial sampling. Muse-class consumer EEG systems have nonetheless been used in research settings for prototyping and validation studies. \cite{Krigolson2017Muse}

For uncertainty, we use MC dropout as a practical Bayesian approximation that enables uncertainty estimates at inference time without changing the trained architecture. \cite{Gal2016Dropout} For calibration assessment, we follow common reliability diagram/ECE methodology and report ECE for both action and finger predictions. \cite{Guo2017Calibration}

\section{Data Acquisition and Persistence}

\subsection{Hardware}

The Muse 2 headset provides four EEG channels:
TP9, AF7, AF8, TP10 sampled at \TargetFsHz~Hz.

\subsection{Streaming Model}

All EEG samples are timestamped in the LSL clock domain. Event timestamps are converted into the same timebase to ensure alignment. Absolute session time is defined as:

\[
t_{\text{session}} = t_{\text{lsl}} - t_{\text{stream\_start}}
\]

\subsection{Persistence Architecture}

Raw EEG samples are first captured and stored as binary NumPy arrays (\texttt{.npy}) to preserve original fidelity and avoid floating-point CSV rounding artifacts. After acquisition:

\begin{itemize}
\item Raw samples are compiled into \texttt{raw/eeg\_raw\_shard\_\*.npy}
\item Event markers are written to both:
  \begin{itemize}
  \item \texttt{events.csv} (legacy human-readable)
  \item \texttt{events.jsonl} (authoritative structured metadata)
  \end{itemize}
\end{itemize}

The JSON file serves as the authoritative event source to prevent schema drift or CSV parsing ambiguity.

By default, sessions persist to disk; however, Step~7 supports an in-memory-only mode via \texttt{--no\_file\_io} that disables all file outputs.

\subsection{Cohort Summary}
Demographics, session duration, and event label counts are derived directly from \texttt{subject.json}, \texttt{run\_meta.json}, and \texttt{events/events.jsonl}. Sex is read from \texttt{subject.json} when available; otherwise it is inferred from the subject ID string when it contains only \texttt{M} or only \texttt{F}.

\section{Preprocessing and Window Extraction}

Sliding windows are extracted using fixed-length windows (window length \WindowSec~s, hop \HopSec~s) resampled to a fixed \TargetFsHz~Hz grid. Each window is assigned an action label (REST/OPEN/CLOSE) and a finger label (NONE/THUMB/INDEX/MIDDLE/RING/PINKY) as defined in \texttt{utils/label\_schema.py}.

The nominal sample count per window is:

\[
N = f_s \times T_{\text{window}} = \TargetFsHz \times \WindowSec
\]

Windows containing non-finite values are excluded during training as an additional safety filter (even though extraction attempts to prevent NaNs). The extracted dataset bundles include artifact and gap flags; in the current run artifacts, the stored counts of flagged windows are summarized in Table~\ref{tab:dataset} (auto-generated below). If additional artifact rejection (e.g., ICA) was applied, it is not logged in the current artifacts and is therefore \NotAvailable.

\subsection{Split Strategy and Leakage Controls}
Training uses a holdout test split (\texttt{test\_size}=0.2) with group-aware splitting (\texttt{split\_mode}=group\_trial) as configured in each run’s saved \texttt{train\_config.json}. The training CLI also includes explicit leakage guardrails: it asserts no group overlap between train/test, supports optional temporal purging (\texttt{purge\_seconds}), and runs a ``window index'' diagnostic intended to detect suspiciously high performance from ordering artifacts (threshold \texttt{window\_idx\_leak\_threshold}). In the current artifacts, \texttt{purge\_seconds}=0.0; therefore, any additional temporal separation beyond group splitting is not enforced.

The window dataset bundles include \texttt{trial\_id} and \texttt{block\_id} fields, but in the current artifacts both are constant (\TrialIdUniqueMin--\TrialIdUniqueMax unique \texttt{trial\_id} values; \BlockIdUniqueMin--\BlockIdUniqueMax unique \texttt{block\_id} values). As a result, strict trial-level evaluation and stratification by trial are not possible for this bundle. Instead, group-aware splitting uses event identifiers (e.g., \texttt{event\_id}/\texttt{event\_index}) when available and assigns additional time-based groups for windows with no event ID (as implemented in \path{utils/splitting.py}).

\subsection{Diagnostics and Quality Controls}
The pipeline includes multiple checks intended to prevent silent failure modes common in streaming EEG systems:
\begin{itemize}
\item \textbf{Finite-value hardening:} \texttt{2\_train\_model.py} removes any windows with non-finite values prior to training to prevent NaN/Inf propagation in PyTorch.
\item \textbf{Leakage guardrails:} \texttt{utils/splitting.py} enforces group-aware splits and provides an optional ``purge'' mechanism (\texttt{purge\_seconds}) to drop training windows near test windows in time.
\item \textbf{Dataset validation:} \path{3b_deepchecks_evaluate.py} produces a per-run HTML report (\path{deepchecks_eeg_report.html}) stored alongside other report artifacts.
\end{itemize}

\section{Model Architecture}

We use a multi-head CNN+LSTM network (\texttt{models/cnn\_lstm\_finger\_action\_net.py}) with shared temporal features and two classification heads (finger and action). The default configuration includes two temporal 1D convolution blocks (16 and 32 channels; kernel sizes 5 and 3), group normalization, dropout, a single-layer LSTM with hidden size 64, and two linear heads. The model has \ModelParamCount trainable parameters.

The loss function is:

\[
\mathcal{L} = \text{CE}_{\text{action}} + \lambda_f \, \text{CE}_{\text{finger}}(\text{non-REST})
\]

Here \(\lambda_f\) corresponds to \texttt{loss\_action\_weight} in \texttt{2\_train\_model.py} and scales the \emph{finger} loss (not the action loss), which is computed only on non-REST windows. The action head supports class weighting, including a configurable REST weight (\texttt{rest\_weight}) saved per run in \texttt{train\_config.json}.

\section{Monte Carlo Dropout for Uncertainty Estimation}

For MC-dropout uncertainty figures (Step~3c), dropout layers remain active at inference time. For \(K\) stochastic passes:

\[
\mu = \frac{1}{K}\sum_{k=1}^{K}\hat{y}_k
\]

\[
\sigma^2 = \frac{1}{K}\sum_{k=1}^{K}(\hat{y}_k - \mu)^2
\]

Reliability diagrams evaluate calibration, while confidence--uncertainty scatter plots provide qualitative uncertainty visualization. Step~3 evaluation is deterministic when predictions are recomputed; however, \texttt{test\_predictions.npz} produced by Step~2 is generated with the model still in train mode, so dropout is active for a single pass unless Step~3 recomputes.

Live inference currently uses deterministic forward passes with confidence gating.

\section{Training Procedure}

Training hyperparameters are saved per run in \texttt{train\_config.json} and summarized in the auto-extracted performance table. In the current artifacts, both runs use 60 epochs, batch size 64, learning rate 0.001, and seed 42. Optimization uses Adam. Early stopping and gradient clipping are \NotAvailable in the current run artifacts (not logged in \texttt{train\_config.json}).

Input normalization is performed using a per-channel normalizer fitted on the training split (\texttt{fit\_channel\_normalizer} in \texttt{2\_train\_model.py}). In the current artifacts, \texttt{loss\_action\_weight} $\in \{1.0, 2.0\}$ and \texttt{rest\_weight} $\in \{0.2, 1.0\}$ (saved per run in \texttt{train\_config.json}); these respectively scale the finger loss and weight the REST class in the action loss, and do not uniformly bias toward REST across runs.

\section{Uncertainty \& Calibration}
From each run’s saved \texttt{test\_predictions.npz}, we compute ECE using the same binning convention as \texttt{3\_evaluate\_model.py} (10 bins over confidence in $(a,b]$). These prediction bundles are generated in Step~2 (single-pass with dropout active in train mode) unless Step~3 recomputes them deterministically. Table~\ref{tab:perf} reports action ECE over all test windows and finger ECE over non-REST windows (defined by action $\neq$ REST). The per-run reliability diagrams (calibration) and MC-dropout confidence scatter plots (uncertainty visualization) are inserted automatically from \texttt{processed/reports/}.

Across subjects, mean action ECE is \ActionECEMean $\pm$ \ActionECESD and mean finger (non-REST) ECE is \FingerECEMean $\pm$ \FingerECESD. Lower ECE indicates better agreement between predicted confidence and empirical accuracy; however, ECE values should be interpreted in light of overlapping-window correlation and potential distribution shift between event segments.

\section{Real-Time Inference and Actuation}
\texttt{7\_live\_infer\_and\_actuate.py} implements online windowing and inference with optional actuation. Actuation decisions are gated by a joint confidence heuristic (minimum of the selected action and finger probabilities), a minimum probability threshold (default \texttt{actuation\_min\_prob}=0.65), a stability requirement over consecutive windows (default \texttt{actuation\_stability}=2), and a cooldown between sends (default \texttt{actuation\_cooldown\_ms}=150). Hardware safety gates prevent any actuation when the predicted action is REST or the predicted finger is NONE.

The runtime additionally tracks recent window latency and logs summary statistics; configuration flags \texttt{latency\_threshold\_ms} and \texttt{latency\_policy} are recorded, but no drop/degrade behavior is currently implemented.

Latency logs from Step~7 are \NotAvailable in the current run artifacts; therefore mean/p95/max inference latency and dropped-window statistics cannot be reported for the present bundle.

\section{Statistical Rigor}
We report per-subject 95\% confidence intervals (Wilson score) for action accuracy over $n_{test}$ windows and for finger accuracy over $n_{non\text{-}REST}$ windows (Table~\ref{tab:perf}). These intervals reflect finite test-set uncertainty under an i.i.d.\ window assumption; they do not account for temporal correlation induced by overlapping windows and event segments, which can narrow effective sample size.

\input{paper_artifacts/tables_bootstrap_ci.tex}

As an additional robustness check, we compute percentile bootstrap confidence intervals over test windows (Table~\ref{tab:bootci}) using the saved per-window correctness vectors. Like the Wilson intervals, these bootstraps assume independent windows and should be interpreted cautiously in the presence of overlap.

\section{Threats to Validity}
Several threats should be considered when interpreting these results:
\begin{itemize}
\item \textbf{Window correlation and leakage risk:} overlapping windows violate i.i.d.\ assumptions. Although group-aware splits are used, correlation within contiguous segments remains.
\item \textbf{Evaluation granularity:} window-level metrics may not reflect trial-level performance; trial IDs in the current artifacts are not informative (constant) and thus cannot support trial-level aggregation.
\item \textbf{Small cohort:} only \NumSubjects subjects are included in the current run artifacts, limiting generalization claims.
\item \textbf{Handedness bias:} both subjects are right-handed; left-handed generalization is untested.
\item \textbf{Demographic completeness:} sex is inferred from the subject ID string (\texttt{M} or \texttt{F}); other covariates are not logged.
\item \textbf{Real-time latency:} Step~7 latency logs are \NotAvailable in current artifacts, so real-time responsiveness cannot be quantified here.
\end{itemize}

For transparency, the window dataset (\texttt{processed/eeg\_windows.npz}) contains, at minimum, the feature tensor \texttt{X} along with per-window labels (\texttt{y\_action}, \texttt{y\_finger}) and timing metadata (\texttt{window\_start}, \texttt{window\_end}). \section{Conclusion}

This work demonstrates an end-to-end, artifact-driven pipeline for finger-level intention decoding from 4-channel consumer EEG with explicit uncertainty and calibration reporting. In the current repository run artifacts, finger decoding on non-REST windows is comparatively stable across subjects (range \FingerAccMin--\FingerAccMax\%) while action decoding exhibits a wider spread (range \ActionAccMin--\ActionAccMax\%). Future work will focus on (i) larger cohorts with richer demographics, (ii) trial-aware protocols that support strict trial-level evaluation, and (iii) logging and reporting of Step~7 latency/throughput to close the loop between offline metrics and real-time deployment behavior.
